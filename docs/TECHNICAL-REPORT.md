# Технический отчёт: локальный прототип «Созвон»

Версия 0.2.2, коммит 6640329. Репозиторий: https://github.com/Shararamoshik/sozvon. Документ описывает то, что реализовано и проверено, и отдельно перечисляет границы, которые прототип не закрывает. Никакие нереализованные возможности здесь не заявлены как готовые.

## 1. Назначение и границы

Приложение помогает подготовить черновик протокола рабочей встречи: принимает аудиозапись или готовый текст, распознаёт речь, позволяет отредактировать расшифровку и собрать структурированный отчёт по выбираемому шаблону, а затем выгрузить документ. Ключевое свойство — каждый пункт отчёта сопровождается дословной цитатой из конкретного сегмента расшифровки; если цитата не найдена, отчёт не сохраняется.

Это технический прототип, а не корпоративная система: он не сертифицирован для закрытого контура, не имеет ролей, аудита и интеграций с СЭД, и при выборе внешнего API отправляет аудио или текст провайдеру после отдельного подтверждения.

## 2. Пользовательский сценарий

- Загрузить аудиофайл, вставить текст встречи или записать звук компьютера (микрофон и системный звук).
- Запустить распознавание: локальной моделью CTranslate2 либо через OpenAI-совместимый API.
- Отредактировать расшифровку: текст и говорящий, поиск и замена; каждая правка создаёт новую версию.
- Создать отчёт по шаблону: язык, подробность, порядок и назначение разделов задаются шаблоном.
- Проверить пункты по цитатам и выгрузить результат в DOCX, PDF, Markdown или JSON.

Загрузка файла сама по себе не вызывает модель и не обращается к сети: распознавание и отчёт — отдельные явные команды. Один запуск соответствует одному запросу; автоматических повторов нет.

## 3. Архитектура

Приложение разделено на слои, а тяжёлые и потенциально нестабильные операции выполняются в отдельном дочернем процессе. Это защищает интерфейс от падений нативного кода аудио и моделей.

```text
web (FastAPI + Jinja + JS)
  -> services (сценарии, очередь заданий, изоляция временных каталогов)
     -> runtime (allowlist операций, обмен JSON-кадрами с дочерним процессом)
        -> audio | llm | export (выполнение в отдельном процессе)
web/services -> storage (SQLite: версии, снимки, истории)
web/services -> config (настройки TOML + ключи в системном хранилище)
```

- Разрешённые операции дочернего процесса: ping, devices, audio_info, transcribe, transcribe_cloud, record, report, render_export.
- Обмен — только JSON-кадры с 4-байтовой длиной; протокол без pickle и shell, с пределом кадра 1 МиБ.
- Временные каталоги распознавания создаёт и удаляет родительский процесс, поэтому принудительное завершение worker не оставляет производных аудиофайлов на диске.
- Отмена задания сигнализирует остановку до ожидания результата; поздний ответ не публикуется.

## 6. Данные и хранилище

Все данные приложения лежат в одном каталоге: база SQLite, загруженные источники, записи, временные файлы обработки и экспорт. Схема создаётся миграциями с резервной копией перед обновлением непустой базы.

| Таблица | Содержимое |
|---|---|
| meetings | встречи: заголовок, тип, статус, длительность, заметки |
| sources | исходные файлы (аудио или записанные дорожки) |
| segments | сегменты расшифровки с таймкодами и говорящим |
| transcript_revisions | история версий расшифровки и их происхождение |
| reports | отчёты, снимок шаблона, снимок ревизии расшифровки, расход токенов |
| templates / template_revisions | встроенные и пользовательские шаблоны с историей |
| jobs | задания: операция, статус, этап, ошибка, снимок параметров |

- Правка расшифровки защищена проверкой ревизии: сохранение с устаревшей базой отклоняется, конфликт двух вкладок не затирает чужой черновик.
- Отчёт навсегда связан со снимком шаблона и ревизией расшифровки: последующее изменение шаблона не меняет уже созданный документ, устаревший отчёт помечается.
- Встроенные шаблоны неизменяемы; редактирование идёт через копию. Недостающие встроенные шаблоны добавляются в существующую базу при запуске, версия схемы при этом не повышается.
- Ключи в базу и снимки заданий не попадают: там только адрес сервиса, модель, лимиты и таймауты.

## 7. Внешние сервисы: контракт и поведение

- Распознавание: multipart-загрузка файла на /audio/transcriptions, ответ с таймкодами; поддерживается локальный режим без сети.
- Отчёт: один POST на /chat/completions (OpenAI-совместимый протокол) либо /v1/messages (Anthropic), без потоковой передачи и без запросов «на проверку» адреса.
- Строгая схема ответа: шесть системных разделов плюс пользовательские; у каждого пункта обязательна цитата, у задачи — явные owner и due (неизвестные значения остаются null).
- Цитата проверяется буквально в указанном сегменте после нормализации пробелов — это защита от выдуманных формулировок, но не доказательство смысловой верности вывода.
- Бюджет ответа и таймаут настраиваются: 256–65 536 токенов (по умолчанию 16 384) и 10–600 секунд (по умолчанию 300). Значения входят в снимок задания.
- Причина остановки модели различается в сообщении: исчерпан лимит (с указанием лимита и счётчиков, включая токены рассуждений), фильтрация, отказ или неизвестное завершение. Незавершённый ответ не сохраняется и не заменяет предыдущий отчёт.

## 8. Безопасность и приватность

- Сервер слушает только 127.0.0.1; вход в интерфейс — по одноразовой ссылке, дальше сессионная cookie и CSRF-заголовок для изменяющих запросов.
- Ключи хранятся в системном хранилище и привязаны к каталогу данных и полному адресу сервиса; смена адреса не переносит ключ автоматически.
- Ответ, содержащий ключ, отклоняется до записи в базу и до передачи дальше — ключ не может попасть в отчёт, событие или журнал.
- Сетевые вызовы: HTTPS для внешних адресов, HTTP только для адресов обратной петли, без перенаправлений и без чтения переменных окружения прокси.
- Ответ провайдера читается потоково с ограничением размера; ошибки проверяются до чтения тела, чтобы не тянуть в сообщения об ошибках содержимое ответа.
- Экспорт прерывается при завершении приложения: недописанный файл не публикуется, временные файлы удаляются.

## 9. Лимиты и защитные пределы

| Параметр | Значение |
|---|---|
| Контекст отчёта | до 64 000 байт UTF-8, без скрытого обрезания |
| Бюджет ответа модели | 256–65 536 токенов (по умолчанию 16 384) |
| Таймаут запроса к модели | 10–600 секунд (по умолчанию 300) |
| Размер ответа провайдера | до 512 000 байт |
| Кадр обмена с процессом-исполнителем | 1 МиБ; результат — до 1 МиБ минус байт |
| Массив сегментов расшифровки | до 921 600 байт |
| Распознавание одного файла | до 1 800 секунд (30 минут) |
| Запись и разбор аудио | до 14 400 секунд (4 часа) |
| Загрузка аудио в облако | 1–100 МБ на запрос (по умолчанию 24 МБ) |
| Сообщение об ошибке | до 500 символов, без содержимого ответа |

Превышение лимита — это отказ с объяснением, а не молчаливое усечение данных.

## 10. Экспорт документов

- DOCX и PDF формируются локально, без установленного Office и без обращения к модели.
- PDF содержит встроенный кириллический шрифт и выделяемый текст; перед записью проверяется покрытие глифов, поэтому символ без глифа приводит к понятному отказу с кодом Unicode и предложением выгрузить DOCX, а не к повреждённому файлу.
- Markdown — читаемый документ; JSON — полный архив, включая историю расшифровки и снимок шаблона.
- Экспорт отчёта по устаревшей ревизии расшифровки отклоняется: сначала нужно пересоздать отчёт.

## 12. Известные ограничения

- Нет автоматического разделения говорящих: спикер проставляется вручную в редакторе.
- Нет словаря отраслевых терминов и оценки уверенности распознавания.
- Нет процесса утверждения и контроля поручений, интеграций с СЭД и почтой.
- Нет ролевой модели, аудита действий и шифрования хранилища — корпоративный контур не закрыт.
- Локальный режим зависит от установленной пользователем модели; качество на технической речи не измерено.
- Одновременно выполняется одна операция распознавания, отчёта или записи и один экспорт.
- Распознавание ограничено 30 минутами на файл: более длинное аудио нужно разделять заранее.

## 13. Направления дальнейшей работы

- Пилот на 10–20 разрешённых или обезличенных записях одного типа встреч: эталон эксперта, время проверки, полнота поручений, число исправлений.
- Интервью с секретарём и руководителем рабочей группы: требования к формату протокола и критериям качества.
- Разделение говорящих и словарь терминов после подтверждения применимости на пилоте.
- Проектирование закрытого контура (локальные модели, роли, аудит) при подтверждённой потребности заказчика.
