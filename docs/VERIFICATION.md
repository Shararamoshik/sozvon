# Проверка технической версии «Созвон»

Проект независим от «Протокола»: собственный git, пакет sozvon, venv, SQLite и Windows-каталог.

## Подтверждено выполнением

- Linux: 451 passed, 1 skipped (Windows-native), один warning стороннего TestClient.
- Windows: 430 passed, 3 skipped (POSIX-only); browser tests и CLI encoding test исключены из этого прогона.
- Ruff production+tests: чисто; синтаксис шести JS-модулей проверен Node.
- Настоящий браузер + FastAPI + SQLite: импорт текста, сохранение заметок, перезагрузка,
  изменение настроек, ширины 1440/1280/1024/640/390, нет горизонтального overflow и pageerror.
- Настоящий CPU STT с отдельно скачанной tiny: синтетическая русская речь распознана в Linux,
  Windows исходниках и Windows EXE. Результат не идеален: «протоколов встречи» вместо
  исходного «протокола встречи» — это демонстрация реального распознавания, не эталон точности.
- Настоящая Windows запись: mic 44100 Hz / mono / 7802 ms, system 48000 Hz / stereo / 7851 ms.
  Независимое чтение файлов подтвердило формат, длительность, peak и RMS. Peak mic 0.1189,
  system 0.9672. Обе дорожки сохранены, предупреждений нет.
- Собран Windows onedir EXE; worker ping/audio_info/STT работают внутри EXE без запуска внешнего Python.
- Финальный EXE повторно записал оба настоящих Windows-источника и прочитал их артефакты;
  отдельный отчёт `D:\sozvon\artifacts\frozen-capture-1790438437909307700\result.json`.
- EXE поднял локальный HTTP, отклонил запрос без сессии, принял разрешённый текст,
  сохранил его и отдал Markdown и локальные шрифты.
- Полный путь отчёта worker -> HTTP -> проверка цитат -> SQLite проверен отдельным
  синтетическим HTTP-сервисом. Это интеграционный тест, а НЕ результат настоящей LLM.

## Найдено и исправлено интеграцией

- Windows import NumPy мог зависать при уже заблокированном читателе входного pipe.
  А/B-проверка показала: обычный импорт проходит, reader-before-import зависает,
  import-before-reader проходит. Нативный импорт до control reader применяется только
  для аудиоопераций на Windows; ping остаётся лёгким. Есть Windows-регрессия.
- Записи было недостаточно 2 секунд на завершение WAV; отдельный бюджет остановки 15 секунд.
- Ошибка декодирования стала понятным JSON 422, а не необработанным 500.
- Замечания аудиопотока не теряются после сохранения; частичный результат обозначается явно.
- Windows-тесты читают исходники с явно указанным UTF-8.

## Не проверено / не входит в готовую первую версию

Реальная LLM с пользовательским ключом, платные API и качество отчётов на настоящих созвонах
не проверены: ключи не запрашивались и пользовательские материалы не отправлялись.
Не проверены GPU, длительная часовая синхронизация, другие Windows-компьютеры,
сертификат подписи, установщик и восстановление записи после отключения питания.
Пока нет полной очереди нескольких задач, редактирования расшифровки, редактора шаблонов,
словаря, DOCX/SRT, просмотра всех версий в UI и автономной LLM в комплекте.
